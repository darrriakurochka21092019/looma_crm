# Проверка первой версии LOOMA.CRM

Версия 1.0.0, 17 октября 2026 года. Приложение реализовано на React + TypeScript, Node.js и PostgreSQL. В архиве находятся исходники, миграции, инструкции, скрипты запуска и CI. Рабочие пароли и база клиентов в него не включены.

## Что выполнено

Сборка клиента и сервера и строгая проверка TypeScript проходят. Выполнены 24 автоматические проверки доменной логики и API; ошибок нет. `npm audit --omit=dev --audit-level=high` не обнаружил уязвимостей производственных зависимостей.

Браузерная проверка выполнена в Chromium: обзор, заказы, карточка заказа, финансы, задачи и настройки; размеры 1440 px, 390 px и 360 px. Ошибок JavaScript и ответов API 5xx в итоговом прогоне не было. На мобильных размерах проверено отсутствие горизонтального переполнения; списки заказов представлены карточками.

Через формы интерфейса создан клиент и заказ на 120 000 ₽, проведены поступление 60 000 ₽, расход 10 000 ₽ и оплата этого расхода. После перезагрузки страницы проверены цена 120 000 ₽, получено 60 000 ₽, долг 60 000 ₽, затраты 10 000 ₽, валовая прибыль 110 000 ₽. Плановая себестоимость 75 000 ₽ не подменяет фактические затраты.

## Ограничения выполненной проверки

В доступной среде нет Docker и возможности запустить нативный PostgreSQL от отдельного системного пользователя. Локальные API-проверки выполнены на PostgreSQL 18 в WASM (PGlite) с тестовым адаптером драйвера. Этот адаптер находится только в среде проверки и не входит в приложение. Штатный сервер использует обычный `pg.Pool` и PostgreSQL.

Подготовлен GitHub Actions workflow с настоящим PostgreSQL 17: сборка, API-проверки, восстановление через pg_dump / pg_restore и аудит зависимостей. Его запуск на GitHub ещё не выполнялся, так как новый репозиторий не создан. Тест восстановления запускается с TEST_RECOVERY=1, использует отдельные временные базы и сверяет суммы, связи и байты документов.

Создание настоящего архива pg_dump и копирование документов проверены локально. Восстановление через TCP-обёртку PGlite не завершено успешно; это не считается подтверждением AC-12. Перед рабочим переносом данных выполните полный сценарий на PostgreSQL 17. Работа Docker Desktop на Windows, восстановление на конкретном компьютере и нагрузка 10 000 заказов / 100 000 операций пока не проверены.

## Осознанные границы первого релиза

Это управленческий учёт, без регламентированной бухгалтерии, банковских интеграций, точного расчёта налоговых обязательств, ЭП и Telegram. Налоговый режим и договорный шаблон утверждает владелец.

План затрат задаётся на уровне изделий; фактические расходы ведутся по категориям. Справочник категорий расходов в интерфейсе пока фиксированный. Коммуникации сохраняются в примечаниях клиента и комментариях задач; отдельной ленты звонков нет. Производственные вложения прикрепляются к заказу как технические документы. Подтверждённые исходящие движения не удаляются; полноценное сторнирование ошибочных выплат — последующий релиз.

Квота учитывает версии документов, шаблоны и исходные файлы импорта. Антивирусная проверка не подключена. Финансовые списки ограничены 1000 актуальных строк на экран, документы и задачи — 500; поиск и пагинация заказов работают через сервер. Для крупного рабочего реестра перед расширением лимитов нужны дальнейшая пагинация финансовых журналов и нагрузочная проверка.

## Перед первыми реальными заказами

Запустите проект по README, измените пароль владельца, задайте начальный остаток, правила резервирования и роли. Проверьте свой обезличенный Excel, утверждённый DOCX, скачивание файлов и восстановление отдельной базы. Сохраните исходные реестры. Для удалённых сотрудников понадобится доступный сервер / локальная сеть; домен сам по себе не публикует локальный компьютер.
