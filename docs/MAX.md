# Задачи в MAX

Уведомления отправляются исполнителю: новое назначение, изменение, завершение, напоминание до срока и просрочка. Работают задачи по заказу и отдельные задачи. Для отменённых и приостановленных заказов сообщения не отправляются.

## Подключение владельцем

1. Зарегистрируйте бота через [MAX для бизнеса](https://business.max.ru/). Возможность создания ботов зависит от правил и доступности кабинета MAX. В настройках своего бота скопируйте токен.
2. В CRM откройте **Настройки → Уведомления в MAX**. Вставьте токен, включите отправку и нажмите **Сохранить MAX**. Кнопка **Проверить бота** проверяет связь без отправки сообщения сотруднику.
3. Передайте сотрудникам ссылку на своего бота. Каждый открывает его в приложении MAX и нажимает **Начать** или отправляет сообщение.
4. При локальном запуске нажмите **Найти ID сотрудников**. Возле нужного сотрудника выберите найденного пользователя, проверьте имя и нажмите **Сохранить привязку**. Известный числовой ID можно вставить вручную. Это именно ID пользователя MAX, а не телефон или имя аккаунта.
5. Создайте задачу этому сотруднику. После запуска сервера обработка очереди выполняется каждые 5 секунд. Сроки проверяются примерно раз в минуту. Состояние последних отправок видно ниже в настройках.

Поиск ID — разовый запрос обновлений бота по нажатию кнопки. Он предназначен для настройки локального приложения и не запускает постоянный Long Polling. Если бот уже подключён к другому приложению через Webhook, вводите ID вручную. Для исходящих уведомлений публичный домен и входящие соединения не нужны. При будущем переносе на хостинг можно сохранить ручные привязки; постоянное получение событий бота следует подключать через Webhook согласно документации MAX.

## Если сообщение не пришло

- Оставьте сервер CRM запущенным; компьютер должен иметь доступ к интернету. После сна или краткого обрыва очередь продолжит работу.
- Проверьте, что сотрудник активен в CRM, привязка и уведомления включены, сотрудник нажал «Начать» у правильного бота.
- Посмотрите состояние отправки. Ошибки сети, ограничение частоты и временные ответы сервера повторяются с увеличением интервала, до 8 попыток. При неверном токене или недоступном получателе исправьте настройки и нажмите **Повторить ошибки**.
- MAX указывает актуальный адрес API `https://platform-api2.max.ru` и необходимость доверия сертификату Минцифры. Если Node.js сообщает об ошибке сертификата, установите официальный доверенный сертификат; для дополнительного PEM-файла Node.js поддерживает `NODE_EXTRA_CA_CERTS`. Укажите путь к этому файлу в системных переменных среды Windows до запуска `start-ready.bat`. Проверка TLS в приложении не отключается. Руководствуйтесь [официальной документацией MAX](https://dev.max.ru/docs-api).

## Хранение и очередь

Токен не возвращается в API настроек и не записывается в журнал действий. Он хранится в закрытом каталоге `storage`, который нужно переносить при обновлении и включать в резервную копию. В качестве альтернативы токен можно передать серверу в переменной `MAX_BOT_TOKEN`; включение уведомлений и получатели всё равно настраиваются владельцем в CRM.

Очередь хранится в PostgreSQL и сохраняется после перезапуска. Для одного пользователя допускается не более одной попытки отправки в секунду. Для одного события и версии задачи создаётся одна запись. Перед отправкой проверяются актуальный исполнитель, версия, статус задачи и статус заказа. После обрыва между принятием сообщения MAX и фиксацией результата в базе возможен повтор: API MAX не предоставляет ключ идемпотентности для этой операции. Это не влияет на сами задачи или оплаты.

Справка: [отправка сообщения](https://dev.max.ru/docs-api/methods/POST/messages), [обновления бота](https://dev.max.ru/docs-api/methods/GET/updates).
