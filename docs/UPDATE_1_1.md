# Обновление LOOMA.CRM до 1.1.0 на Windows

Эта инструкция подходит, если CRM уже работает через `start-ready.bat` и в ней есть ваши заказы.

1. Найдите чёрное окно запущенного сервера. Нажмите **Ctrl+C**; если появится вопрос о завершении пакетного файла, введите **Y** и нажмите Enter.
2. Сохраните старую папку `LOOMA.CRM` целиком как копию. PostgreSQL хранит базу отдельно от этой папки. Резервную копию базы можно сделать в pgAdmin: справа нажмите на базу `looma` → **Backup… / Резервная копия…** → укажите файл → **Backup**.
3. Распакуйте **новый** архив `LOOMA_CRM_READY.zip` в другую папку, например `LOOMA_UPDATE`. Откройте находящуюся внутри папку `LOOMA.CRM`: в ней должен быть `start-ready.bat`.
4. Из прежней папки скопируйте в новую **файл `.env` и папку `storage`**, если она есть. Они должны оказаться рядом с новым `start-ready.bat`. Копировать старые `dist`, `dist-web`, `db`, `scripts` или `node_modules` не нужно.
5. Дважды нажмите **новый `start-ready.bat`**. При первом запуске могут установиться зависимости. Изменения базы применятся автоматически: существующие заказы, пользователи, оплаты и документы сохраняются.
6. Откройте **http://localhost:3001**. В браузере нажмите **Ctrl+F5**. Внизу меню должна быть версия **v1.1**. Входите с прежними логином и паролем.

Старую папку пока оставьте как копию. Одновременно запускайте только один сервер CRM. Рабочую базу не создавайте заново, демонстрационное заполнение не запускайте.

## Что изменилось

- Приостановленные и отменённые заказы видны в «Заказы → Архив». Их суммы, долги, расходы и движения исключены из общих расчётов. История сохранена в карточке. Возобновление возвращает заказ и его задачи в рабочие списки.
- Можно выбрать несколько документов сразу: до 10 файлов, до 25 МБ каждый, всего до 100 МБ. При ошибке не сохраняется вся партия.
- Менеджер имеет доступ ко всем рабочим разделам, включая финансы, отчёты, все документы, задачи команды и историю. «Настройки» остаются у владельца.
- В форме задачи есть выбор «По заказу» / «Отдельная задача», в общем разделе — фильтр по типу.
- В настройках владельца появился MAX. Для отправки нужен собственный бот, его токен и привязка сотрудников: [инструкция](MAX.md).
- Обрыв неиспользуемого соединения PostgreSQL больше не завершает сервер. При недоступной базе появляется сообщение, после восстановления можно обновить данные. Компьютер с PostgreSQL и окно сервера должны оставаться включёнными.
