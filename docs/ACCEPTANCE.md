# Проверка LOOMA.CRM

Версия 1.3.0, 20 октября 2026 года. Приложение реализовано на React + TypeScript, Node.js и PostgreSQL. Исходники, миграции, инструкции, скрипты запуска и CI находятся в репозитории; готовый архив содержит собранное приложение. Рабочие пароли и база клиентов в него не включены.

## Обновление 1.3.0

Добавлены первое знакомство, полная экскурсия с подсветкой и стрелками, отдельные подсказки по разделам и формам, пропуск, продолжение и справка с поиском. Прогресс хранится в PostgreSQL отдельно для учётной записи и роли; локальный кеш позволяет продолжать при временной ошибке синхронизации.

На настоящем PostgreSQL 18.4 локально прошли 47 из 49 тестов; два сценария восстановления и обрыва соединения запускаются отдельно в GitHub CI с PostgreSQL 17. Новый API-тест проверяет все роли, независимость пользователей и ролей, сохранение прогресса, отказ анонимному пользователю, недопустимые поля запроса и неизменность рабочих данных.

В Chromium полностью пройдены 51 шаг владельца, 40 менеджера, 36 бухгалтера и 23 мастера. Дополнительно пройдены полная экскурсия владельца на ширине 390 px и экскурсия мастера без доступных заказов. Проверены закрытие и продолжение после обновления страницы, пропуск, отсутствие повторного приветствия после завершения, FAQ с поиском, обучение поверх незавершённой формы клиента и закрытие справки через Esc. Новый браузерный контекст без localStorage получил сохранённый прогресс с сервера. Заказы, клиенты, движения денег, задачи, документы и настройки до и после обучения совпадают; ошибок JavaScript в итоговом прогоне нет.

Готовый ZIP распакован в отдельную папку и запущен через `scripts/start-ready.mjs` на чистой базе с установкой только рабочих зависимостей. Проверены версия 1.3.0, вход, API прогресса, клиент, заказ, загрузка файла, фото изделия и создание всех четырёх документов. Нативный модуль паролей и инструменты сборки не устанавливаются. Проверка готовой сборки в CI дополнена чтением и сохранением прогресса через API: это также проверяет включение новой миграции и общего модуля в архив.

## Обновление 1.1.0

Добавлены проверки исключения приостановленных и отменённых заказов из финансов, долга, выплат, неоплаченных резервов, графиков, XLSX, общих документов и задач; проверяется обратное включение при возобновлении. Проверены несколько файлов за один запрос, откат при повреждённом файле, превышении числа файлов и квоты, права менеджера и отделение задач по заказу от самостоятельных. Очередь MAX проверяется с подменённым HTTP: назначение, версия, сохранение после сетевой ошибки, дедупликация, просрочка, точные int64 ID, ответы 401/429 и исключение архивных заказов. Реальная доставка в пользовательский MAX требует токена и получателей; чужой токен при тестах не используется.

В CI добавлен тест с `pg_terminate_backend`: закрывается idle-соединение настоящего PostgreSQL, затем проверяются здоровье сервера и авторизованный запрос.

На PostgreSQL 17 и Node.js 24 прошёл 31 тест без пропусков, включая восстановление резервной копии и принудительный обрыв соединения. Готовый архив проверен запуском на чистой базе; зависимости готовой сборки проверены на Windows. [Прогон 1.1.0](https://github.com/darrriakurochka21092019/looma_crm/actions/runs/39119002095).

В Chromium пройдены создание задачи из заказа, отдельная задача и фильтр, загрузка двух PDF одной формой, приостановка и архив заказа, экран MAX на 1440 и 390 px, вход менеджера и финансовый раздел без доступа к настройкам. Ошибок JavaScript и ответов API 5xx в итоговом прогоне нет.

## Ранее выполненные проверки 1.0

Сборка клиента и сервера и строгая проверка TypeScript проходят. На GitHub Actions с Node.js 24 и PostgreSQL 17 выполнены 25 автоматических проверок доменной логики, API и восстановления; ошибок нет. `npm audit --omit=dev --audit-level=high` не обнаружил уязвимостей производственных зависимостей. [Успешный прогон](https://github.com/darrriakurochka21092019/looma_crm/actions/runs/39069957318).

Браузерная проверка выполнена в Chromium: обзор, заказы, карточка заказа, финансы, задачи и настройки; размеры 1440 px, 390 px и 360 px. Ошибок JavaScript и ответов API 5xx в итоговом прогоне не было. На мобильных размерах проверено отсутствие горизонтального переполнения; списки заказов представлены карточками.

Через формы интерфейса создан клиент и заказ на 120 000 ₽, проведены поступление 60 000 ₽, расход 10 000 ₽ и оплата этого расхода. После перезагрузки страницы проверены цена 120 000 ₽, получено 60 000 ₽, долг 60 000 ₽, затраты 10 000 ₽, валовая прибыль 110 000 ₽. Плановая себестоимость 75 000 ₽ не подменяет фактические затраты.

| AC-06 Возврат                   | Пересчитывает полученную сумму и долг; избыточный возврат отклонён                        |

| AC-08 Задача мастера            | Назначенная задача и технический файл доступны; чужой заказ закрыт                        |

| AC-11 Изменение цены            | Автор, прежние и новые суммы и изделия сохраняются в аудите                               |

Дополнительно проверены черновики, повтор платежа с тем же ключом, одновременные повторы запросов, конфликты версий, полный рабочий доступ менеджера при запрете настроек, исправление расходов без уменьшения ниже оплаченного, смена срока задачи, приглашения, отзыв сессий, XLS, XLSX, выбор листа, шаблон DOCX с обязательным утверждением и Excel-отчёт.

## Ограничения выполненной проверки

Первоначальный локальный прогон выполнен на PostgreSQL 18 в WASM (PGlite) с временным адаптером драйвера. После публикации в GitHub те же сценарии успешно повторены на настоящем PostgreSQL 17 со штатным `pg.Pool`. Тестовый адаптер не входит в приложение.

GitHub Actions проверяет сборку, API, восстановление через pg_dump / pg_restore и зависимости. Тест восстановления запускается с TEST_RECOVERY=1, использует отдельные временные базы и сверяет суммы, связи и байты документов. Проверка выявила и позволила исправить копирование файлов в уже существующий пустой каталог восстановления.

В отдельном задании на Ubuntu успешно выполнены сборка Docker-образа и запуск полного Compose-проекта из чистого checkout. Проверены готовность приложения и базы, выдача JavaScript интерфейса, создание владельца, вход, создание клиента и заказа, загрузка PDF и скачивание с точным совпадением байтов. [Успешный прогон API и Docker](https://github.com/darrriakurochka21092019/looma_crm/actions/runs/39070125503).

Работа Docker Desktop на Windows, восстановление на конкретном компьютере и нагрузка 10 000 заказов / 100 000 операций пока не проверены. Перед рабочим переносом данных проверьте запуск и копию на своём компьютере.

## Осознанные границы первого релиза

Это управленческий учёт, без регламентированной бухгалтерии, банковских интеграций, точного расчёта налоговых обязательств, ЭП и Telegram. Налоговый режим и договорный шаблон утверждает владелец.

План затрат задаётся на уровне изделий; фактические расходы ведутся по категориям. Справочник категорий расходов в интерфейсе пока фиксированный. Коммуникации сохраняются в примечаниях клиента и комментариях задач; отдельной ленты звонков нет. Производственные вложения прикрепляются к заказу как технические документы. Подтверждённые исходящие движения не удаляются; полноценное сторнирование ошибочных выплат — последующий релиз.

Квота учитывает версии документов, шаблоны и исходные файлы импорта. Антивирусная проверка не подключена. Финансовые списки ограничены 1000 актуальных строк на экран, документы и задачи — 500; поиск и пагинация заказов работают через сервер. Для крупного рабочего реестра перед расширением лимитов нужны дальнейшая пагинация финансовых журналов и нагрузочная проверка.

## Перед первыми реальными заказами

Запустите проект по README, измените пароль владельца, задайте начальный остаток, правила резервирования и роли. Проверьте свой обезличенный Excel, утверждённый DOCX, скачивание файлов и восстановление отдельной базы. Сохраните исходные реестры. Для удалённых сотрудников понадобится доступный сервер / локальная сеть; домен сам по себе не публикует локальный компьютер.
